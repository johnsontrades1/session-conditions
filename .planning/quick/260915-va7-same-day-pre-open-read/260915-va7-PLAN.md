<objective>
Fix the one-session lag: at 7:40 CT the page renders yesterday's completed
session because it can only build a feature row once that day's OHLC exists.
Split pre-open features (all already computed from completed-session data
only — atr20, range_5_20, prev_range_atr, trend_20_atr, er_10, pos_20d,
rv5_rv20, vix/vix_term/vix_rank_1y, event flags) from the gap (open-dependent,
unknowable pre-open). Render a forward row dated for the NEXT session by
default. Backtest untouched — historical df keeps every feature and outcome.
</objective>

<context>
Traced every whitelisted feature's dependency chain in features.py's build():
each one already uses only .shift(1)'d closes/highs/lows or rolling windows
that exclude the row's own OHLC (that's the whole point of "pre-open
features" per the module docstring). The only reason a forward row can't
exist today is that build()'s output is indexed 1:1 with the input price
frame, and the last row in that frame is always the last COMPLETED session.
Appending one phantom row (NaN OHLC) dated for the next trading day and
re-running the existing build() machinery produces correct values for every
whitelisted column with zero changes to the feature formulas themselves —
verified by hand-tracing the shift/rolling chain for atr20, vix, and
event_flags (event_flags is pure calendar lookup, works for any date).
</context>
